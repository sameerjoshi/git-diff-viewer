Installation

macOS: Download the .dmg from Releases, open it, and drag the app to Applications. On first launch you may need to right-click the app and choose Open to bypass Gatekeeper since the app is ad-hoc signed.

Windows: Download the .exe installer and run it. The app installs and launches automatically.

Linux (Ubuntu/Debian):

sudo dpkg -i git-diff-viewer_1.0.0_arm64.deb

From source:

git clone https://github.com/sameerjoshi/git-diff-viewer.git
cd git-diff-viewer
npm install
npm start
Requires Node.js 18+ and git installed on your system.

Usage

  1. Open a repository — click "Open Repository" or press Ctrl+O (Cmd+O on macOS) to select a folder. Recently opened repos appear in a quick-access list.
  2. View changes — the left sidebar shows all changed files with status badges (MODIFIED, UNTRACKED, DELETED, RENAMED, NEW). Click any file to see its unified diff on the right.
  3. Stage files — use the checkbox next to each file to stage it, or check "ALL" to stage everything. Clicking an already-staged file will unstage it.
  4. Commit — type a summary (required) and optional description at the bottom, then click "Commit to branch".
  5. Switch branches — click the branch dropdown in the header, search or select a branch. Type a new name and press Enter to create and switch to a new branch.

The file list refreshes automatically when files change on disk — no need to manually refresh.

Architecture

The app follows strict Electron process separation with four files:

index.html
Renderer (UI)
→
preload.js
Context Bridge
→
main.js
IPC + Electron
→
git-helpers.js
Business Logic
  • index.html — single-file renderer containing all markup, CSS, and JavaScript. No framework, no build step.
  • preload.js — context bridge that exposes window.gitAPI with 12 methods and 1 event listener.
  • main.js — Electron main process handling IPC, file watching (chokidar), and window lifecycle.
  • git-helpers.js — pure business logic extracted for testability: file status dedup, recent repos CRUD, synthetic diffs, error formatting.

Data flows left-to-right: renderer calls window.gitAPI.*, preload forwards via ipcRenderer.invoke, main.js handles and returns { ok, data } or { error } objects. No thrown exceptions cross the IPC boundary.

File watching is started when get-status is called — two chokidar watchers monitor the working tree and .git/ internals, pushing a repo-files-changed event to the renderer which triggers a status refresh.

Building from source

npm run build        # Linux (.deb)
npm run build:mac    # macOS (.dmg)
npm run build:win    # Windows (.exe)
Cross-platform builds may require additional tools. macOS builds need to run on macOS. See the electron-builder docs.

Testing

Unit tests cover the extracted business logic in git-helpers.js:

npm test             # run all tests (Jest)
npm run test:watch   # run in watch mode

35 tests covering file status deduplication, synthetic diff generation, branch error formatting, recent repos CRUD, and window state persistence.
